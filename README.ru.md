# cryptoledger

Демонстрационное ядро двойной записи на Go. Клиент отправляет перевод и теряет ответ. При повторе с тем же ключом сервер возвращает исходный идентификатор, подпись и балансы на момент операции. Это можно проверить через gRPC с клиентским сертификатом.

```sh
docker compose up -d --build --wait
docker compose exec ledger ledgerctl demo
```

На чистой базе результат — 1 USDT на счёте игрока, одна транзакция, две проводки и одна запись аудита. При повторном запуске используется тот же ключ. Первый запуск включает загрузку образов и сборку. После проверки останови контейнеры командой `docker compose down`. Данные останутся в томах Docker.

Без Docker запусти `go run ./cmd/demo` с Go 1.26. Сценарий использует временную SQLite и собственные сертификаты.

| Что проверяется | Как это увидеть |
|---|---|
| Десять клиентов одновременно повторяют перевод | [Интеграционный тест на PostgreSQL](internal/ledger/postgres_test.go) |
| Сумма проводок одной транзакции равна нулю | [Отложенная проверка в БД](deploy/postgres/schema.sql) |
| Сумма проводок одного счёта равна его балансу | [Сверка журнала](internal/ledger/verify.go) |
| Подписанный перевод и цепочка аудита проходят проверку после рестарта | `docker compose restart ledger`, затем `docker compose exec ledger ledgerctl verify` |

На общей схеме платформы проект реализует блок Ledger. Подписи ставит программный Ed25519-ключ, который сохраняется в томе контейнера. Разграничение полномочий клиентов, аппаратное хранение ключей и внешнее закрепление хеша аудита описаны как ограничения.
